# What's built, in detail

How each part of the editor was built and what it covers, in the order it was built. `docs/HANDOVER.md` has the short version; `docs/DECISIONS.md` has the reasons.

## Phase 2: the port to a real codebase (done)

`prototype/` was the reference until the new app reached parity in step 7. The suggested layout for the new code was:

```
src/
  model/     classes.ts (registry), document.ts, commands.ts (undo/redo), assets.ts (images)
  layout/    layout.ts (pure functions)
  export/    luau.ts, html.ts, json.ts
  render/    canvas.ts (DOM renderer), overlay.ts
  editor/    interactions.ts (drag, resize, snap), keyboard.ts
  ui/        Explorer, Properties, Ribbon, ExportDialog (React components)
tests/       Vitest unit tests and Playwright end-to-end tests
```

1. **Scaffold.** Vite, TypeScript (strict), React for the panels, Vitest, Playwright, ESLint and Prettier. Done when `npm run dev` serves an empty editor shell and `npm test` runs both the unit tests and the existing prototype smoke test.
2. **Model.** A typed class registry with per-class property schemas, so UIGradient uses its real names (Color, Transparency, Rotation). Document types, plus commands with undo and redo instead of snapshots. Done when unit tests cover insert, delete, reparent, property edits, undo and redo. Website follow-up, also done: the DataModel root with StarterGui and Site, Page and Breakpoint classes, changes per breakpoint read through `resolveProps`, the image library, Link values, and project file version 3, which still opens version 1 and 2 files. From here on, each step also builds its website part (findings: https://claude.ai/code/artifact/d0980ca9-4396-4ec4-b9a6-b7b0784430c8).
3. **Layout engine.** A pure function from document and screen size to boxes. Done when unit tests reproduce every layout number the prototype produced, plus edge cases: AnchorPoint (1, 1), negative offsets, Scale padding, list alignment Center and Right, horizontal lists, aspect ratios and invisible list items. Done in `src/layout/`: every box of the sample menu matches the prototype on all five device presets. Website part, also done: pages are window-wide, Scale inside them is a fraction of the window, the page grows to fit its content, and layout reads each object's values at the current breakpoint.
4. **Exporters.** Luau, HTML and JSON as pure functions. Done when the output for the sample project is byte-identical to `prototype/examples/` (or every difference is intentional and explained) and the Luau parses with luaparse. Roblox part done in `src/export/`: the Luau (both targets) and HTML for the sample menu are byte-identical to the goldens. The project file is version 3 now, so it differs from `sample-project.json` on purpose (see step 2). Website part, also done: `exportSite` writes an HTML file per page (`/pricing` is `pricing/index.html`, NotFound is `404.html`) and the pictures it uses, with each breakpoint's changes as media queries. Objects gained web-only Link, HtmlTag and AltText. A Playwright test checks that every exported page matches the layout engine at desktop, tablet and phone widths. Still at the base values on every breakpoint: Scale corner radii under 0.5, aspect ratios and TextScaled.
5. **Renderer and interactions.** DOM canvas, selection overlay with handles and the AnchorPoint dot, drag, resize, smart snapping, nudge, zoom and device presets. Done when Playwright tests cover the same interactions as `tests/smoke.mjs`. Done in `src/editor/` and `src/ui/viewport/`: `tests/e2e/canvas.spec.ts` covers select, drag (Offset stays Offset), resize, click-to-select-child, undo and redo, preview, devices and phone width, plus snapping, nudging, zoom and the keyboard (delete, duplicate, copy, paste). The Properties and Explorer parts of the smoke test (shorthand input, To Scale, drag-to-reparent) belong to step 6. Website part, also done: the viewport shows the Roblox screens or one page; a page shows Desktop, Tablet or Phone and edits that breakpoint's values; pages are drawn as long as their content, with a line where the first screen ends; and links work in preview.
6. **Panels.** Explorer with drag-to-reparent, rename and keyboard navigation; Properties with typed editors and Studio shorthand; ribbon; export dialog; Code tab. Done when every Properties editor type has a test. Done in `src/ui/` and `src/editor/`, in the editor design's look (light and dark): `tests/e2e/panels.spec.ts` edits every value type (string, int, number, bool, enum, alpha, color, vec2, udim, udim2, image, colorseq, numseq, asset, link) and covers the rest of the smoke test (shorthand input, To Scale, drag-to-reparent), plus rename, the Explorer keys, insert menus, the Code tab, export downloads and project files. Website part, also done: on a page shown at Tablet or Phone, Properties edits that breakpoint (a dot marks values changed there, and clicking it goes back to the inherited value); Link, HtmlTag and AltText show only for objects on a page; pages and pictures (preview, favicon, social image) can be added from the panels; the export dialog downloads the site as `website.zip`. The Project menu starts a new website or Roblox UI, opens the sample, and opens and saves project files; the project autosaves in the browser.
7. **Parity and cleanup.** Walk through the prototype side by side, fix gaps, then move `prototype/` to `legacy/` or delete it. Parity checked: the sample menu renders the same as the prototype on every device (only sub-pixel text differences), every class has the prototype's properties, defaults and options (plus the web-only ones), and its editing behaviors work in the new app. The walkthrough found two gaps. Ctrl+Z with nothing to undo said nothing (the prototype shows a message), and the exported HTML page, in both apps, read sizes in whole pixels, so aspect ratios and Scale corners were up to half a pixel off. `tests/e2e/html-export.spec.ts` now checks every exported object against the layout engine on every device, and new browser tests cover what only the prototype's smoke test did (cut, Escape, Shift-resize, reordering in the Explorer, preview typing and scrolling). Cleanup, also done: Armin chose to delete `prototype/` rather than keep a `legacy/` copy that nothing would test. Its smoke test went with it, the golden exports moved to `tests/golden/`, and `npm run update-golden` rewrites them from the app.

## Public beta and later features (done)

After Phase 2 comes the public beta: templates, share links, side-by-side devices, the live code view, .rbxmx export and an accessibility pass. Armin picked templates first, then asked for AutomaticSize.

1. **Templates.** Done. "New from a template…" in the Project menu shows three websites (landing page, portfolio, link in bio) and four Roblox screens (shop, inventory, settings, HUD), each previewed by the viewport's own Stage. They are built in code in `src/model/templates/` with the `Builder` the samples use (`src/model/builder.ts`), so every edit goes through the same commands as the editor. The websites set Tablet and Phone values (stacked cards, smaller headlines, a hidden nav); the Roblox screens are sized in Scale with UIAspectRatioConstraints, so they fit every device. `tests/unit/model/templates.test.ts` checks each one is valid, survives a project file, stays on screen (or inside the window's width) on every device, and exports Luau that parses; the export browser tests check every template's HTML against the layout engine. The website templates grow with their text (see Small upgrades below); the Roblox screens use TextScaled, which fills its box instead.
2. **AutomaticSize.** Done. Every object except a ScrollingFrame has AutomaticSize (None, X, Y or XY), right after Size in Properties, and it can differ per breakpoint. The layout engine grows the box to fit its content, and Size is the smallest it gets. Text counts by its bounds: wrapped at the box's width when TextWrapped is on, and on X growing only as wide as the parent before it wraps. A UIListLayout counts its items and gaps, free-placed children count to their far edge (AnchorPoint included, nothing above or left of the box), and UIPadding is added. The content is measured with the box at its Size, width first; then the children are placed in the grown box, so a child sized in Scale stretches with it. TextScaled text and hidden children don't count, and an empty TextBox counts its placeholder. Text is measured by the browser with the same styles the Stage and the exports draw with (`src/ui/viewport/text-measure.ts`), and again once web fonts load; Node tests use the estimate in `src/layout/text.ts`. The Luau export writes `AutomaticSize`. The HTML exports mark these objects with `data-auto` and a `--auto` CSS variable, which media queries can change, and the inline script grows them the same way and then lengthens the page. `tests/e2e/auto-size.spec.ts` checks every box of a screen and a site full of growing objects against the engine measuring text in the same page. Still missing: UISizeConstraint.
3. **Side-by-side devices.** Done. "Side by side" in the viewport's bar draws every device next to each other at one zoom: Desktop, Tablet and Phone for a page (one per breakpoint), Laptop, Tablet and Phone portrait for the Roblox screens (plus the device picked in the menu, if it's another). One device takes the edits, marked by its name above it and by the Device size menu; a press on another device, or on its name, makes that one the edited device without moving anything, so a drag on the phone edits Phone. The rulers, the grid and the handles follow the edited device; the others outline the selection and the hover. `sideBySideScenes` in `src/editor/editor.ts` lays them out, and `sceneOf` caches a scene per device. The bar hides the Percent and Pixels legend, then the toggle's words, when it gets narrow, so it stays on one line.

4. **Small upgrades.** Done. Text objects have LineHeight (1 to 3, a multiple of TextSize, which may differ per breakpoint): the Stage, the text measurer, the HTML exports (`line-height`, written only when it isn't 1) and the Luau export use it. A ScrollingFrame has AutomaticCanvasSize: the layout engine grows its canvas to fit the children and their padding, CanvasSize being the smallest it gets, measured as AutomaticSize measures a box (`canvasOf` in `src/layout/layout.ts`); the HTML exports mark it `data-canvas` with a `--canvas` variable, and the inline script grows the canvas. The three website templates now use both: headings and paragraphs have a line height and AutomaticSize Y, the sections, cards and columns around them grow too (their old sizes are now the smallest they get, so the templates look as before), and badges and the main buttons grow sideways with their text. `tests/e2e/site-export.spec.ts` now runs the layout engine in the page and measures text there, since template boxes depend on their text.
5. **.rbxmx export.** Done. The export dialog has a "Roblox model" tab that downloads the Roblox screens as a model file, every screen (`framecraft-ui.rbxmx`) or one picked from a menu (named after it). In Studio, right-click StarterGui, choose Insert from File and pick it. `exportRbxmx` in `src/export/rbxmx.ts` writes the same objects and base values as the Luau, with every property written out in Roblox's own types: enums as numbers from Roblox's API dump, fonts as FontFace. It was checked with `tools/rbxcheck`, Rojo's file reader (rbx_xml with Roblox's reflection database, which flags unknown properties, wrong types and enum values) on the sample, every Roblox template and an object of each class with every font, then written to Roblox's binary format; it has not been opened in Studio yet (see the Studio checks in `docs/HANDOVER.md`). `tests/golden/sample-menu.rbxmx` keeps the sample's file, and the browser tests read a download with the browser's XML parser.

6. **Page background.** Done. A click (or right-click) on page space no object covers selects the page, outlined along the device's edge, and hovering there outlines it too, so its BackgroundColor3 is one click away. Pages also have BackgroundTransparency (it can differ per breakpoint): the editor shows the measuring grid through a see-through page, and the website export writes it into the body's `rgba` color, where a browser shows its own window color (white) behind it. On the Roblox screens a click on empty space still selects nothing, since ScreenGuis have no background of their own; the backdrop menu changes what's behind them.
7. **Components browser.** Done. A Components button in the ribbon's Insert group opens a drawer beside the Explorer (it takes the Explorer's place on windows under 1440 px, and becomes a sheet on narrow ones) with 33 pre-made components from the "Pre-made component ideas" doc: 14 website sections, 13 Roblox pieces and 6 basics for both, all things the editor can already build. It shows what fits the view (or All), with search and categories; a click opens a bigger preview where Light or Dark and Rounded or Sharp change the look, and pieces that need a script to work carry a "Look only" tag. Add, a double-click or a drag onto the viewport drops a plain copy, one undo step, which is then edited like anything else (linked copies came in step 13). Where it lands: a website section goes to the end of the page; a block goes into the selection (or the nearest object that can hold it, as Insert does), last in a list or centered and nudged, and straight onto a page it gets a section of its own; a Roblox piece keeps its own place on the screen. Components are built in code in `src/model/components/` with the `Builder`, from a palette per look in `theme.ts`; changes for Tablet and Phone move to the project's breakpoints by name (`componentSubtree`). Previews are drawn by the viewport's own Stage. `tests/unit/model/components.test.ts` builds every component in every look and checks its layout and Luau; the export browser tests check every component's HTML against the layout engine (which found the screens page missing a margin reset on heading tags, now fixed), and `tests/e2e/components.spec.ts` covers the drawer. Grid layouts, scripts, BillboardGui and ViewportFrame pieces from the ideas doc wait for those features.

8. **Shapes and SVG pictures.** Done. A Shapes button in the ribbon's Insert group opens a grid of 24 shapes (`src/editor/shapes.ts`, `src/ui/ShapesMenu.tsx`). Rectangle, rounded rectangle, circle, pill and line are Frames (with a UICorner, and a UIAspectRatioConstraint for the circle), so they export to Roblox exactly. The others (ellipse, triangles, polygons, stars, arrow, chevron, plus, heart, speech bubble, ring, half circle, lightning) are ImageLabels showing a white SVG that stretches with the box, tinted by ImageColor3. Roblox can't load SVG, so in Studio these need an uploaded picture's asset id like any image; Armin said to leave images out of the Roblox exports, so there is no PNG conversion. ImageColor3 now tints pictures everywhere, as Roblox's multiply: the Stage and both HTML exports use one SVG color-matrix filter per color (`tintDefs` in `src/export/html.ts`), and picture styles moved into CSS rules so breakpoints can change them. Image objects take SVG files (`src/ui/pictures.ts` cleans them: no scripts, event handlers or javascript: links, and a size from the viewBox), and pasting SVG code (as icon sites copy it) or an image, or dropping image files on the viewport, inserts an ImageLabel. A one-color SVG (black or currentColor) is made white and gets ImageColor3 black, so it looks the same and can be recolored.
9. **Fonts, weights and letter spacing.** Done. Text objects have Font (a family), FontWeight (Thin 100 to Heavy 900) and FontStyle (Normal or Italic), the parts of Roblox's FontFace. The Font field opens a searchable menu that shows each font in its own letters: 27 web fonts (Inter, Poppins, DM Sans, Plus Jakarta Sans, Geist, Fraunces, Playfair Display, JetBrains Mono and more) and Roblox's own, web fonts first on pages and Roblox's first on the screens. FontWeight lists the weights the font has, with their numbers, next to a Bold toggle; Ctrl+B and Ctrl+I toggle bold and italic on the selection. `src/model/fonts.ts` holds every family with its Google Fonts weights (each checked against Google Fonts), its kind for the CSS fallback and its Roblox family; a weight the web font lacks draws its nearest. Project files and code that use the older names (GothamBold) are read as a family and a weight. On pages, text has LetterSpacing in pixels (it can differ per breakpoint), drawn by the Stage, measured for AutomaticSize and exported as `letter-spacing`. The sample site and the website templates now use web fonts, with tighter letter spacing on big headlines: Fraunces and Inter for the coffee site and the portfolio, Plus Jakarta Sans for the landing page and DM Sans for the link in bio. The Roblox exports are unchanged for Roblox fonts; see `.claude/rules/exporters.md` for web fonts.
10. **Folders, multi-select, the object menu and panning.** Done. A Folder (insert menu, or Ctrl+G on a selection) groups objects as in Roblox: they draw and lay out as if they sat in the Folder's parent, placed by their own Position even where a UIListLayout arranges the parent's other children, and AutomaticSize counts them as free-placed. `drawnChildren`, `folderObjects` and `drawnParent` in `src/model/document.ts` are the one place that rule lives; the layout engine gives a Folder its parent's content area as its box, the Stage and both HTML exports draw its objects in the parent (the inline script counts absolutely placed children as free in a list), and the Luau and the model file write it as a plain Folder. Folders sit in ScreenGuis, pages, objects and other Folders, not in StarterGui, and hold objects but not modifiers. Ctrl+Shift+G ungroups. Several objects can be selected: Ctrl or Cmd and click adds one (Explorer and canvas), Shift and click selects a range in the Explorer and adds on the canvas, a box drawn from empty space selects the objects fully inside it, and Ctrl+A selects the selection's siblings. `EditorState.selected` holds them all; `selection` is the one picked last, which Properties shows and the handles resize. Dragging, nudging, delete, duplicate, copy, paste, hide, unit conversion and dragging rows in the Explorer work on all of them (without objects inside another selected one); Properties shows the properties they share with the last one's values (≠ marks those that differ) and an edit changes all of them as one step. Right-click on an Explorer row or the canvas (or Shift+F10 and the menu key on a row) opens the object menu (`src/ui/ObjectMenu.tsx`), whose Delete goes through `deleteSelection`. The middle mouse button, or Space and drag, pans the canvas. `tests/e2e/selection.spec.ts` covers the clicks, the menu, box select and panning; `tests/unit/layout/folder.test.ts` the Folder rules and exports.

6. **Web extras.** Done. Things a website can do that Roblox can't, all web-only, so they show in Properties only for objects on a page and the Luau and model file skip them:
   - **UIHover**, a modifier ("Hover" in the ribbon, on pages only): while the mouse is over the object it takes the UIHover's BackgroundColor3, BackgroundTransparency and TextColor3, grows by Scale (1.05 to start) and moves up by Lift pixels, over Duration seconds. A new one copies its object's colors, Tablet and Phone ones included, so it only grows until edited. The export writes `:hover` rules and a transition (on a button with AutoButtonColor, the hover colors replace the darkening; a press still darkens); the editor shows it in preview.
   - **BackgroundBlur** (pixels, may differ per breakpoint): `backdrop-filter: blur()`, frosted glass behind a see-through background. The editor draws it too.
   - **Appear** (Fade, SlideUp, SlideLeft, SlideRight, Zoom) and **AppearDelay**: the object plays the animation once, the first time it scrolls into view. The export adds a small script with an IntersectionObserver only when an object uses it; without the script, or with reduced motion asked for, everything simply shows. The editor plays it in preview.
   - **Pinned**, for objects straight on a page: in the page's list it sticks to the window's top as the page scrolls past (`position: sticky`); placed freely it stays put on the window, in a fixed layer inset like the page's content. Pinned objects draw above the rest of the page. The editor keeps them in view as the canvas scrolls in preview.
   - **UIStroke Top, Right, Bottom and Left**: a Border stroke can leave sides out on the website (a line under a nav, a bar beside a quote). Each side is its own box-shadow, with the corner between two drawn sides filled in. Roblox draws all four, so the Roblox screens ignore them.

   `tests/unit/export/web-extras.test.ts` and `tests/e2e/web-extras.spec.ts` cover them. Embeds, forms, text styles, filters, cursors and smooth scrolling came next (Web extras, part two, below). Not built yet: drop shadows (Roblox has UIShadow now, so it would be a Roblox class) and hover states beyond these (an outline or a child that shows).

11. **Web extras, part two.** Done. Also website only, so Properties shows them only on pages and the Luau and model file skip them:
   - **Form**, a web-only object (the ribbon's Web menu, on pages only, or the insert menu): it starts as a contact form, an email field, a message box and a Send button in a UIListLayout. Its TextBoxes are the fields, named by their Name, with InputType (Email, Phone, Number, Url and Password get the right input; LongText is a textarea) and Required; its TextButtons and ImageButtons without a Link become submit buttons. It sends to Action, an address from a form service such as Formspree (Method POST or GET): a small script sends it without leaving the page (`Accept: application/json`), empties it, and the buttons say SentText; on an error they say so and stay pressable. Without the script, or for a mailto: Action, the browser sends it the usual way. In preview, a press on its button says where it sends.
   - **Embed**, a web-only object (Web menu: YouTube video or Map): Kind YouTube takes a link (watch, youtu.be, shorts, embed or a bare id, with `t=` as the start) and plays from youtube-nocookie.com, muted when Autoplay is on; Kind Map shows Source, an address or a place, from Google Maps at Zoom 1 to 20. Neither needs a key (`src/model/embeds.ts`). The export is an iframe with a Title for screen readers; the editor shows the video's thumbnail or a map pin while editing and the real thing in preview. An Embed holds no objects (the class's `leaf` flag), only modifiers.
   - Forms and Embeds stay on pages: the insert menus offer them only there, and inserting or moving one outside a page is refused by the commands (`pageOnly` in `src/model/document.ts`).
   - **Text:** TextDecoration (Underline, Strikethrough; Ctrl+U on a page) and TextCase (Uppercase, Lowercase, Capitalize), per breakpoint. TextCase changes the letters AutomaticSize measures. Italic already came with FontStyle.
   - **Gradient text:** a UIGradient on a TextLabel or TextButton has ApplyTo (Background or Text). Text paints the letters with the gradient times TextColor3 (`background-clip: text`) and leaves the background plain; contrast checks read each gradient color. Gradient letters have no outline. In Roblox a UIGradient tints a label's text too, so a label with a see-through background and a gradient should look the same in Studio (not checked yet).
   - **Picture filters** (Filters section): Grayscale, Sepia, Brightness, Contrast, Saturation and Blur, per breakpoint, after the ImageColor3 tint (`pictureFilter`).
   - **Cursor** on every object: the mouse pointer over it on the website and in preview.
   - **SmoothScroll** on the Site (on by default): a page with a link to one of its own sections glides there (`scroll-behavior: smooth`, unless people ask for less motion), and so does preview.
   - The website checks also list forms with no Action and embeds with nothing to show.

   `tests/unit/export/web-more.test.ts` and `tests/e2e/web-more.spec.ts` cover them; the browser tests send a form to a stand-in Formspree address.

12. **Live code view.** Done. A Code button in the viewport's bar (beside Side by side) opens a panel under the viewport, the full width between the Explorer and Properties, with a height dragged from its top edge (or the arrow keys there; it's remembered in the browser). It replaced the Code tab in Properties, so code and properties show at once. On a page it shows the page's HTML file beside its CSS; on the Roblox screens, the Luau for Studio's command bar; "HTML & CSS" and "Luau" switch between them (the Roblox screens' web page, or the screens' Luau from a page). The code is the exporters' own, read through `src/editor/live-code.ts`: the HTML with its `<style>` and scripts folded to one line each, the style sheet one declaration per line (`prettyCss`), long data addresses shortened, and every line tagged with the object it belongs to, from the classes the HTML writer gives each element (`exportSiteMapped`, `exportHtmlMapped`) and the Luau variable names (`exportLuauMapped`). The selection's lines are marked and scrolled to (a modifier marks its parent's CSS), hovering a line outlines its object and clicking selects it, and lines that change flash for a moment as you edit or drag, scrolling into view if none shows. Copy file (or Copy all) takes the export exactly as it downloads, and in Luau, Copy plus the object's name takes just its subtree. The code follows edits a moment behind when they come fast (`useDeferredValue`), and on a page only that page is written (about 2 ms for the sample). `tests/unit/editor/live-code.test.ts` checks every object on the sample and the website templates owns lines, and `tests/e2e/panels.spec.ts` covers the panel.

13. **Linked components.** Done. They work like Roblox Packages: right-click an object and pick Make component (Ctrl+Alt+K, or Cmd+Option+K). The object becomes the first copy, and its duplicates, pastes and the copies added from the drawer's new Yours section (Add, a double-click, or a drag onto the viewport) are linked copies. An edit to any copy changes every copy, objects added or deleted inside it included. Each copy keeps its own text, pictures and links (Text, PlaceholderText, Image with its preview, AltText, Link, an Embed's Source and Title), and a copy's root its own place, size and name (Position, Size, AnchorPoint, Rotation, LayoutOrder, ZIndex, Visible, Pinned, Name); changes per breakpoint follow the same split. The Explorer marks a copy's root, Properties shows which component an object follows with Reset (the component's text, pictures and links again) and Detach (Ctrl+Alt+B, plain objects again), and a purple dot marks each of the copy's own values, which a click puts back. The drawer's Yours preview can add a copy or delete the component (its copies stay as plain objects). How it works (`src/model/linked.ts`): `Doc.components` keeps each component's tree once, keyed by its own ids, and every object of a copy carries `copyOf` (the component and the key it follows). Copies stay ordinary objects in the tree, so layout, the Stage, the live code and every export read them as before and write plain copies (real Packages need publishing to Roblox). After each command, `syncCopies` finds the copies it touched: an edited one updates the component, which then rebuilds every other copy; a new one (pasted or duplicated) is made to follow its component. A copy put inside another becomes part of it, an object taken out of a copy becomes plain, and a second copy of one object (pasted inside the copy) joins the component. An edit that spread is recorded as a `replace` command of the exact instances before and after, so undo and redo bring back the same ids. Project files are version 4. `tests/unit/model/linked.test.ts` covers the model and `tests/e2e/linked.spec.ts` the editor. Not yet: renaming a component, variants, and copies inside copies.

6. **Accessibility pass.** Done. Editor: F6 and Shift+F6 move between the app bar, ribbon, Explorer (or the Components drawer), canvas, the Code panel when it's open, and Properties; the canvas takes focus, so the arrow keys nudge from there and the keyboard scrolls it; tab lists (Properties and Code, the export formats) follow the arrow keys; the insert menu's search is a combobox that says the highlighted class; popovers move focus in, and the AnchorPoint grid follows the arrows. Screen readers get the page's h1, a live message for every toast and for a selection made outside the Explorer, and only the Explorer's view of the objects while editing (the drawing is hidden from them); in preview, links and buttons take focus and Enter follows a link. Motion stops when the system asks for less. The theme tokens pass WCAG AA in both themes (text 4.5:1 on each surface, also hovered or selected; icons and the focus ring 3:1), which `tests/unit/ui/tokens-contrast.test.ts` checks; dark's faint, accent and danger and light's faint got a little stronger. The user's own designs: `src/editor/contrast.ts` works out text contrast against what's drawn behind it (see-through layers and gradients blended over the page; a picture, or the game behind a Roblox screen, means it can't tell), Properties shows it under Text, and the Website export tab lists `siteChecks` (`src/editor/checks.ts`): low contrast on any device, links with no words, pages with no h1, each with a Show button. The sample site, website templates and Roblox templates pass (darker accents and grays, an h1 on the sample's Pricing page); the sample menu keeps the prototype's colors, so its PlayButton shows a contrast warning. Exports: links and inputs get a visible focus ring, a TextBox's input is labeled with its placeholder, and picture placeholders are hidden from screen readers. `tests/e2e/a11y.spec.ts` runs axe on the editor in both themes with its menus and dialogs open, and on every page the sample and the website templates export. After the editor-feature PRs merged, the same pass covered them: Shift+F10 or the menu key opens the right-click menu on the canvas too (beside the selection), Shift+Up and Shift+Down grow the Explorer selection with one Tab stop for the tree, a selection of several objects is announced as a count, the delete popup's live region is always present and it stays while its buttons have focus, the color picker's swatches say which is current, and objects ignored under a UIListLayout read in a quieter color instead of fading below contrast. axe also runs with the color picker, right-click menu, several selected objects, delete popup and Components drawer open. A TextButton with no Link still exports as a div, since it does nothing on a website.

## Known gaps

The app inherited these from the prototype. Step 6 closed one of them: the Explorer has keyboard navigation now.

Layout and rendering

- UIListLayout flex features (HorizontalFlex, VerticalFlex, Wraps, UIFlexItem) are not modeled.
- UIAspectRatioConstraint only does FitWithinMaxSize; AspectType and DominantAxis are ignored.
- UIGradient has two stops and is Linear only. It tints the background, or the text with ApplyTo Text on pages; Roblox also tints images. Offset, Scale and TileMode are missing.
- UIStroke is drawn outside the box with `box-shadow`, and text outlines are approximated with a ring of text-shadows. BorderStrokePosition, LineJoinMode and StrokeSizingMode are missing.
- Missing classes: UIShadow, UISizeConstraint, UITextSizeConstraint, UIGridLayout, UIPageLayout, per-corner UICorner radii, SurfaceGui, BillboardGui.
- Missing properties: RichText, TextTruncate, BorderMode (Outline assumed; the legacy border hides when a UICorner exists).
- ScrollingFrame can't scroll in edit mode (no CanvasPosition) and the scrollbar isn't drawn.
- TextScaled is approximated by fitting text in the browser (whole sizes, max 100).
- Resizing a rotated object doesn't keep the opposite edge fixed on screen, and snapping is off for rotated objects.
- No safe-area or top-bar overlay.

Editing

- No align and distribute, and no lock. (Multi-select, box select and Folders exist.)
- Copy and paste use an in-page clipboard, not the system clipboard.
- Undo history is lost on reload. The project itself autosaves to localStorage.

Exports

- No import from Studio. The .rbxmx export exists, but nobody has inserted one in Studio yet.
- The HTML export needs a small inline script for Scale corner radii, aspect ratios and TextScaled.
